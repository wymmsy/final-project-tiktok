#### Шаг 1: Baseline запуски

Задача агенту: сделать soft-delete сущности FavouriteVideo. Промпт:

> сделай мягкое удаление (soft delete) сущности FavouriteVideo. не удаляй ничего, пометь сущность как удаленную (is_deleted). также измени код, чтобы эта сущность нигде не использовалась

Было сделано 3 прогона в разных ветках. Агент уточнял, сделать ли удаление из базы данных перед 3 прогоном.

_**Проверка прогонов**_

Был создан скрипт scripts/check_architecture.py, который проходится по файлам .cs и .json и проверяет соответствие правилам. Выводит 3 типа нарушений:
1. `ERROR` — грубые нарушения структуры (импорты из api в domain и application, пустое исключение и т. д.)
2. `WARNING` — не ломает структуру проекта, но плохое решение или нарушение конвенций языка разработки
3. `INFO` — мелкие недочеты, которые не должны идти в прод

#### Шаг 3: AGENTS.md и skill

В файле AGENTS.md сообщается общая информация по проекту, структура файлов и инструкции для сборки и запуска тестов. Далее идут архитектурные правила
связи Domain, Application, Infrastructure и Api. Далее конвенции кода и правила оформления, включая имена переменных, обработку ошибок и временные метки для этапа разработки. Следующие правила касаются коммитов, например, агент должен спрашивать разрешение перед коммитом в origin.
